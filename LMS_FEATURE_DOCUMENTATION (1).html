0. System-Wide Notes

  • Root Path Organization: The workspace is split into two major root folders:
    • /frontend: Built with React, Vite, TypeScript, Tailwind CSS, and TanStack Query.
    • /backend: Built with Java, Spring Boot 3.2.4, PostgreSQL, and Hibernate/JPA.
  • Backend context path: server.servlet.context-path = /api/v1 configured in backend/src/main/resources/application.yml. Every backend controller route is relative to /api/v1 (e.g. @RequestMapping("/auth") becomes /api/v1/auth).
  • Frontend Base URL: Configured in frontend/src/lib/apiClient.ts as baseURL = "http://localhost:8080/api/v1" (or dynamically mapped) to seamlessly communicate with the Spring Boot server.
  • Real DB Authentication: Real user signup, login, session persistence, and role-based route protection are fully operational. Authentic credentials are validated against the PostgreSQL users table.
  • The React Routing Engine: Fully driven by react-router-dom inside frontend/src/App.tsx. Supports deep nesting, dynamic segment matching (e.g., /course-detail/:id), role-based protections, and layout framing.
  • Soft Deletes: The system implements soft-deletion. Entities like courses, categories, and content blocks set is_active = false instead of doing a hard SQL deletion, preserving records and relationship integrity.

Feature 1: User Authentication, Registration & Session Management

1. Feature Purpose

Secures the application by restricting access to authorized users. It supports two enterprise roles: admin (full catalog write operations, curriculum authoring, category creation) and student (read-only catalog browsing, course details, learning, and enrollment simulation). On login/registration, the backend generates an authentication session token.

  • Frontend API Auth Service: frontend/src/services/authService.ts

  • Backend Hibernate User Entity: backend/src/main/java/com/geeknito/geeknito_backend/entity/learning/UserEntity.java

3. Exact Working Flows

Flow A: User Login Flow

User types email and password on the Login Page <Login /> ↓ Clicks "Sign In" button -> handleSubmit() trigger ↓ Login Page calls authService.login(email, password) ↓ apiClient sends POST HTTP request to "/auth/login" with { email, password } ↓ AuthController.login() receives the request: - Sanitizes and lowercases the input email. - Queries UserRepository.findByEmail(email). - If user not found -> Returns 401 Unauthorized ("Invalid credentials. User does not exist."). - Compares the plain-text passwords. If mismatch -> Returns 401 ("Invalid email or password."). - Verifies user.isActive() flag. If false -> Returns 403 Forbidden ("This user account has been deactivated."). - Generates an "educorp-jwt-token-stub-{id}" token. ↓ AuthController returns 200 OK with AuthResponse DTO (id, fullName, email, role, token) ↓ authService receives response.data and returns it to <Login /> ↓ <Login /> triggers login(response) in AppContext: - Sets "currentUser" state to the returned user profile. - Sets "userRole" state to the user's role ("admin" or "student"). - Synchronizes profile and role states to browser LocalStorage: * "educorp_user_profile" -> JSON string * "educorp_user_role" -> "admin" | "student" - Fires success toast: "Welcome back, {fullName}!" ↓ <Login /> navigates programmatically to "/courses" using react-router-dom useNavigate()

Flow B: User Registration / Signup Flow

User toggles to Signup Mode in <Login /> and fills out Name, Email, Password ↓ Clicks "Create Account" -> handleSubmit() trigger ↓ Calls authService.register(fullName, email, password) ↓ apiClient sends POST HTTP request to "/auth/register" with { fullName, email, password } ↓ AuthController.register() receives the request: - Validates email is not blank and password length >= 6. If invalid -> Returns 400 Bad Request. - Normalizes email to lowercase. - Checks UserRepository.existsByEmail(normalizedEmail). If true -> Returns 409 Conflict. - Resolves user role: * If request contains role parameter ("admin" or "student"), sets it. * Else if the email string contains the substring "admin", automatically promotes to "admin". * Otherwise, defaults to "student". - Instantiates a UserEntity, sets isActive=true, and commits it via UserRepository.save(). ↓ AuthController returns 210 Created with AuthResponse DTO including the generated database ID and token ↓ authService receives response.data and returns it to <Login /> ↓ <Login /> triggers login(response) in AppContext (persists profile + role to LocalStorage) ↓ Fires success toast: "Account successfully created for {fullName}!" ↓ Navigates programmatically to "/courses" via react-router-dom useNavigate()

Flow C: Client-Side Route Protection Flow (ProtectedRoute)

Admin or Student triggers a page change (e.g. typing "/wizard" or "/categories" or navigating to details) ↓ React Router parses Route elements inside App.tsx and matches the route path ↓ The matched route is wrapped in <ProtectedRoute> element ↓ ProtectedRoute checks userRole and currentUser states from AppContext: - If userRole is null (no active session): * Aborts rendering the children. * Redirects immediately to "/login" using react-router-dom <Navigate to="/login" replace />. - If userRole exists, but the Route requires a restricted list of allowedRoles (e.g. allowedRoles={["admin"]} on "/wizard" or "/categories") and userRole is "student": * Fires error toast via showToast("Access Denied: You do not have permission to view that page.", "error"). * Aborts rendering the admin page. * Redirects Student back to "/courses" using react-router-dom <Navigate to="/courses" replace />. - Otherwise (role matches permissions): * Renders children elements inside <Outlet /> wrapper.

Feature 11: Cross-Cutting Infrastructure

The LMS system relies on several non-functional components to coordinate cross-cutting operational stability:

1. Centralized Axios client (frontend/src/lib/apiClient.ts)

Ensures consistent API calls. Translates client requests, appends Bearer tokens if present, and intercepts response errors. It normalizes Spring Boot server failures into a standardized ApiError schema containing clean HTTP status codes, readable text messages, and network indicators.

2. Global Controller exception mapper (backend/src/main/java/com/geeknito/geeknito_backend/exception/GlobalExceptionHandler.java)

A global controller advice filter. Captures unexpected Spring Exceptions at runtime and maps them to clean HTTP responses:

  • EntityNotFoundException / ResourceNotFoundException -> Maps to 404 Not Found.
  • IllegalArgumentException / MethodArgumentNotValidException -> Maps to 400 Bad Request.
  • Database uniqueness constraint violations / other unhandled exceptions -> Maps to 500 Internal Server Error.

3. Soft Delete Schema Convention

Every Hibernate DB Entity (CategoryEntity, CourseEntity, ModuleEntity, SubmoduleEntity, and ContentEntity) contains an is_active boolean property. Deletions do not execute DELETE FROM commands; they run updates setting is_active = false, which filters elements from read lists while preserving relational histories.

                                              └───< [ContentEntity] (N) [submodule_id FK, soft-deleted]
